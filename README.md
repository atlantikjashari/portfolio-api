# portfolio-api

The Django REST Framework backend behind the **Backend Lab** on my portfolio
(`/backend`). Every widget there calls this API live and shows the real request,
status code, timing and JSON response.

**Stack:** Python 3.13 · Django 5.2 · Django REST Framework · SimpleJWT ·
drf-spectacular · PostgreSQL (Neon) · WhiteNoise · gunicorn · Render ·
pytest + GitHub Actions

## Endpoints

| Feature | Method + path | Notes |
|---|---|---|
| API root | `GET /api/` | lists the endpoints |
| Health | `GET /api/health/` | no DB query by default, so it never wakes the database. `?deep=1` also checks the DB |
| Contact | `POST /api/contact/` | serializer validation, honeypot field, throttled (`5/hour`), saved to the DB, optional e-mail via Resend |
| Projects | `GET /api/projects/`, `GET /api/projects/<slug>/` | managed in Django admin, `?featured=true` filter |
| Guestbook | `GET/POST /api/guestbook/` | paginated, validation, moderation flag (`GUESTBOOK_AUTO_APPROVE`), links auto-held for review |
| Live stats | `POST /api/stats/hit/`, `GET /api/stats/` | anonymous page views (hashed visitor IDs), response cached (DB cache) |
| JWT auth | `POST /api/auth/token/`, `POST /api/auth/token/refresh/`, `GET /api/auth/me/` | public demo account, `/me/` needs `Authorization: Bearer <token>` |
| API docs | `/api/docs/` (Swagger UI), `/api/redoc/`, `/api/schema/` | generated by drf-spectacular |
| Admin | `/admin/` | contact messages, projects, guestbook moderation |

There's no Celery/Redis worker: free hosts don't run background workers. The
course behind this project covered task queues, and the Backend Lab says so.

## Local setup

Requires Python 3.13+.

```bash
python -m venv .venv
# Windows (Git Bash): source .venv/Scripts/activate   ·   macOS/Linux: source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env          # DEBUG=True locally; DATABASE_URL empty = SQLite
python manage.py migrate
python manage.py createcachetable
python manage.py bootstrap    # creates the demo user (+ superuser if DJANGO_SUPERUSER_* are set)
python manage.py createsuperuser   # or this, for local admin access
python manage.py runserver    # http://localhost:8000/api/
```

To let the local frontend call the API, keep `CORS_ALLOWED_ORIGINS=http://localhost:3000`
(the Nuxt dev server). Add `http://localhost:4173` if you preview the static build there.

### Tests

```bash
pytest                       # 37 tests: contact, projects, guestbook, stats/health, auth
```

GitHub Actions (`.github/workflows/tests.yml`) runs the same suite against
PostgreSQL 17 on Python 3.13 and 3.14 on every push to `main` and every pull request.
It also runs `manage.py check --deploy` and fails if a migration is missing.

## Environment variables

All settings come from the environment. `.env` is only for local use and is
never committed. `DEBUG` defaults to `False`.

| Variable | Required in prod | Example / default | Purpose |
|---|---|---|---|
| `DEBUG` | – | `False` | never `True` in production |
| `SECRET_KEY` | **yes** | Render generates it | Django + JWT signing key |
| `DATABASE_URL` | **yes** | `postgresql://…neon.tech/neondb?sslmode=require` | empty locally = SQLite |
| `ALLOWED_HOSTS` | – | `api.example.com` | Render's own hostname is added automatically |
| `CORS_ALLOWED_ORIGINS` | **yes** | `https://atlantik-portfolio.pages.dev` | the only browser origins allowed to call `/api/` |
| `CORS_ALLOWED_ORIGIN_REGEX` | – | `^https://[a-z0-9-]+\.atlantik-portfolio\.pages\.dev$` | allow Cloudflare preview deploys |
| `CSRF_TRUSTED_ORIGINS` | **yes** | `https://portfolio-api.onrender.com` | needed for admin login over HTTPS |
| `NUM_PROXIES` | – | `1` on Render | read the real client IP for throttling |
| `RESEND_API_KEY` | – | `re_…` | contact-form e-mail notifications. Without it, messages are still saved |
| `RESEND_FROM` | – | `Portfolio <onboarding@resend.dev>` | sender. Use your own domain once it's verified in Resend |
| `CONTACT_NOTIFY_EMAIL` | – | `atlantik.jashari@gmail.com` | where notifications go |
| `DEMO_USERNAME` / `DEMO_PASSWORD` | – | `demo` / `demo-portfolio-2026` | public JWT demo account (no permissions) |
| `GUESTBOOK_AUTO_APPROVE` | – | `True` | `False` = every entry waits for approval in admin |
| `DJANGO_SUPERUSER_USERNAME` / `_EMAIL` / `_PASSWORD` | – | | admin account created at deploy (Render free has no shell) |
| `THROTTLE_CONTACT`, `THROTTLE_GUESTBOOK`, `THROTTLE_AUTH`, `THROTTLE_STATS`, `THROTTLE_ANON` | – | `5/hour`, `10/hour`, `20/hour`, `120/hour`, `600/hour` | rate limits |
| `STATS_CACHE_SECONDS` | – | `60` | stats cache lifetime |

## Deploy: Render (free) + Neon (free Postgres)

Free tiers were checked on 16 Oct 2026. They change often, so re-check the pricing pages.

- **Render free web service:** no card needed. It sleeps after 15 minutes idle and takes about a minute to wake up. You get 750 instance hours a month.
- **Neon free:** no card needed. 1 GB per project and 100 CU-hours a month; the database sleeps after 5 minutes idle.

Render's own free Postgres expires after 30 days, so this project uses Neon for the database.

### 1. Database: Neon
1. Sign up at <https://neon.tech> → **New project**. Pick region **AWS Europe (Frankfurt)**, close to the Render service.
2. **Connect** → copy the connection string with **pooling turned off** (a direct connection works best with Django's persistent connections).
   It looks like `postgresql://USER:PASSWORD@ep-xxxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`.

### 2. Push this repo to GitHub
```bash
git init && git add . && git commit -m "Portfolio API"
git branch -M main
git remote add origin https://github.com/atlantikjashari/portfolio-api.git
git push -u origin main
```
(Create the empty `portfolio-api` repository on GitHub first. If you pick another
name, also change `repoUrl` in the frontend's `app/pages/backend.vue` and
`repo_url` in `app/data/projects.ts`.)

### 3. Web service: Render
1. Sign up at <https://render.com> with GitHub → **New → Blueprint** → choose this repo.
   Render reads `render.yaml`, which creates the free service in Frankfurt, sets `DEBUG=False`, generates `SECRET_KEY` and adds the health check.
2. Fill in the values it asks for:
   - `DATABASE_URL`: the Neon string from step 1
   - `CORS_ALLOWED_ORIGINS`: your frontend URL, e.g. `https://atlantik-portfolio.pages.dev` (no trailing slash)
   - `CORS_ALLOWED_ORIGIN_REGEX`: optional, see the table above
   - `CSRF_TRUSTED_ORIGINS`: the service URL, e.g. `https://portfolio-api.onrender.com`. If you don't know it yet, set it after the first deploy.
   - `RESEND_API_KEY`, `CONTACT_NOTIFY_EMAIL`: see step 4 (they can stay empty for now)
   - `DJANGO_SUPERUSER_USERNAME`, `DJANGO_SUPERUSER_EMAIL`, `DJANGO_SUPERUSER_PASSWORD`: your admin login (use a strong password)
3. **Apply.** Each deploy runs `build.sh`, which installs the requirements and then runs
   `collectstatic`, `migrate`, `createcachetable` and `bootstrap` (demo user + superuser).
   The start command is gunicorn (see `render.yaml`).
4. Check it: `https://<service>.onrender.com/api/health/` should return `{"status": "ok", …}`,
   `/api/docs/` should show Swagger, and you should be able to log in at `/admin/`.

### 4. Contact e-mails: Resend (optional, free 100 e-mails/day)
1. Sign up at <https://resend.com> → **API Keys → Create** (permission: *Sending access*).
2. On Render, set `RESEND_API_KEY` to that key and `CONTACT_NOTIFY_EMAIL` to the **same
   e-mail address you signed up to Resend with**. Without a verified domain, Resend only
   delivers from `onboarding@resend.dev` to your own address.
3. Optional: verify your own domain in Resend, then set `RESEND_FROM=Portfolio <hi@yourdomain>`.

If Resend is down or not configured, the message is still saved and shows up in `/admin/`.

### 5. Connect the frontend
Set `NUXT_PUBLIC_API_BASE=https://<service>.onrender.com` in Cloudflare Pages
(see the frontend README) and redeploy it. When the frontend's domain changes, update
`CORS_ALLOWED_ORIGINS` here.

### Alternative host: Koyeb
The `Dockerfile` runs the same app on Koyeb or any Docker host. Migrations and
`bootstrap` run on container start. Use the same environment variables, with `NUM_PROXIES=1`
and your Koyeb hostname in `ALLOWED_HOSTS`.

```
apps/core/         health, stats (+ caching, hashed visitors), middleware, bootstrap command
apps/contact/      contact model, serializer, throttled view, Resend notification
apps/projects/     project model + admin, seeded via migration 0002
apps/guestbook/    guestbook with pagination + moderation
apps/accounts/     JWT login/refresh, protected /me
tests/             pytest-django suite
build.sh           Render build script
render.yaml        Render Blueprint
Dockerfile         optional container image (Koyeb)
```
